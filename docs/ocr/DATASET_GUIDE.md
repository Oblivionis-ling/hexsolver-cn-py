# OCR 测试集制作指南

这份文档说明当前阶段 OCR 需要多少测试样例、应该怎么标注，以及本地标注工具怎么使用。现阶段目标是先把 OCR 优化变成可量化的工程问题，而不是只靠肉眼感觉判断准不准。

## 1. 需要多少张测试样例

建议分三阶段做，不需要一口气做完。

第一阶段：`15-20` 张截图。

- 用来开始优化 OCR。
- 必须包含当前已经失败或容易失败的截图。
- 每张图尽量完整标注 `REMAINING`、外侧行线索、格内线索。
- 这个阶段的目标是快速找到最明显的问题，例如行线索锚点偏移、符号 `{}` 或 `-` 识别错误。

第二阶段：`30-50` 张截图。

- 用来作为日常回归测试集。
- 每次改 OCR 后都跑这批图，观察正确率是否真的提高。
- 建议覆盖不同关卡、不同棋盘大小、不同剩余数量、不同分辨率。

第三阶段：`80-120` 张截图。

- 用来接近稳定版本。
- 这个阶段才适合讨论“默认自动填入是否足够安全”。
- 如果之后要训练专用小模型，这个数量仍然偏少，但已经足够指导模板 OCR 和几何裁剪优化。

更重要的是标注项数量。第一阶段最好先做到：

- `REMAINING`：至少 `15-20` 个。
- 外侧行线索：至少 `300` 个。
- 格内线索：至少 `150` 个。

如果只能少量开始，我建议先做 `20` 张高质量截图，而不是做很多低质量截图。

## 2. 截图应该怎么选

一批好的 OCR 测试图应该覆盖这些情况：

- 普通清晰截图：约 `50%`。
- 外侧行线索密集、靠边或靠角的截图：约 `20%`。
- 有 `{n}` 连续线索和 `-n-` 非连续线索的截图：约 `20%`。
- OCR 当前明显失败的截图：约 `10%`。

截图要求：

- 尽量使用原始截图，不要微信、QQ、网页二次压缩。
- 游戏窗口尽量完整，不要裁掉顶部 `REMAINING`。
- 不要截到动画过渡帧。
- 尽量记录截图来源，例如分辨率、缩放比例、关卡或随机盘编号。

## 3. 标注内容

每张图建议标注三类 OCR 对象。

### 3.1 REMAINING

类型选 `REMAINING`。

文本只写数字，例如：

```text
17
```

框选时只框住数字本身即可，不需要框住 `REMAINING` 这个英文标签。

### 3.2 外侧行线索

类型选 `行线索`。

文本格式必须统一：

```text
3
{3}
-3-
?
```

方向可以选：

- `竖直`
- `右下斜`
- `左下斜`
- `未知方向`

如果你暂时分不清方向，选 `未知方向` 也可以。优化几何锚点时，我会用程序重新推断方向。

### 3.3 格内线索

类型选 `格内线索`。

文本格式同样统一：

```text
2
{2}
-2-
?
```

坐标可以先不填。当前最重要的是让 OCR 有真实文本和真实框。

## 4. 测试集目录

本地默认目录是：

```text
tests/
  images/       原始测试截图
  labels/       每张截图对应一个 JSON 标注文件
  reports/      后续 OCR 评估报告
  crops/        后续导出的 OCR 调试裁剪图
```

标注文件示例：

```json
{
  "version": 1,
  "image": {
    "file": "3-1.png",
    "width": 1920,
    "height": 1080
  },
  "items": [
    {
      "id": "A0001",
      "target": "remaining",
      "text": "17",
      "box": [1520, 94, 1565, 126],
      "family": "unknown",
      "coord": "",
      "note": ""
    },
    {
      "id": "A0002",
      "target": "row",
      "text": "{3}",
      "box": [420, 210, 462, 238],
      "family": "vertical",
      "coord": "",
      "note": ""
    }
  ],
  "notes": ""
}
```

## 5. 本地标注工具

我已经写了一个轻量标注工具：

```text
tools/ocr_dataset_tool.py
```

它不需要额外安装新软件，直接使用当前 Python 环境里的 `Pillow` 和系统自带 `Tkinter`。

### 5.1 初始化目录

```powershell
.\.conda_env\python.exe tools\ocr_dataset_tool.py --init
```

### 5.2 导入已有测试图

你的旧测试图在：

```text
D:\Desktop\HexInfinite\test
```

可以直接导入：

```powershell
.\.conda_env\python.exe tools\ocr_dataset_tool.py --import-dir D:\Desktop\HexInfinite\test
```

### 5.3 打开图形标注工具

```powershell
.\.conda_env\python.exe tools\ocr_dataset_tool.py
```

操作方式：

1. 点击“导入图片”，或先用命令导入图片。
2. 在图片上按住左键拖出 OCR 文本框。
3. 右侧选择类型，填写真实文本。
4. 点击“添加标注”。
5. 标完一张图后点击“保存”。
6. 用“上一张 / 下一张”继续标注。

快捷键：

- `Ctrl+S`：保存当前标注。
- `Delete`：删除当前选中的标注。

### 5.4 检查统计

```powershell
.\.conda_env\python.exe tools\ocr_dataset_tool.py --summary
```

它会输出：

- 图片数量
- 标注文件数量
- `REMAINING` 数量
- 行线索数量
- 格内线索数量
- 缺少标注的图片
- 格式不合法的标注

## 6. 我建议你先怎么做

第一轮先做 `20` 张图。

优先级如下：

1. 先导入当前 `D:\Desktop\HexInfinite\test` 里的图。
2. 再补 `8-10` 张普通清晰截图。
3. 再补 `5` 张你觉得 OCR 特别容易错的截图。
4. 再补 `3-5` 张包含 `{n}` 和 `-n-` 的截图。

每张图先标：

- `1` 个 REMAINING。
- 所有外侧行线索。
- 所有带数字或符号的蓝格/黑格。

如果时间有限，最优先标外侧行线索，因为当前 OCR 最大的不稳定点就在这里。

## 7. 后续我会怎么用这批数据

有了测试集以后，我可以继续做这些事情：

- 写 OCR 回归评估脚本，统计每张图的命中率。
- 导出当前程序自动裁剪的行线索图，和人工标注框对比。
- 优化行线索锚点和旋转归一化。
- 比较 RapidOCR、模板 OCR、PaddleOCR 的实际正确率。
- 把低可信 OCR 改成候选提示，不再自动送进求解器。

我的建议是：先不急着换大 OCR 模型。我们先用这套测试集把“错在哪里”量出来，然后再决定是强化模板、改几何，还是接入 PaddleOCR 做对照。
