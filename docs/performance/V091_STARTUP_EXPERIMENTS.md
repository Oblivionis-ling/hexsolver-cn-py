# 0.9.1 启动性能与恢复弹窗实验

## 目标

解决两个相互关联但根因不同的问题：单文件程序打开后长时间没有窗口，以及存在自动存档时“是否继续上次盘面”确认框没有稳定出现在最前面。优化不得改变地图生成、求解层级、步骤结论、模拟推演或存档数据。

## 基线定位

开发机为 Windows 11 x64、Python 3.11、PySide6 6.11.1、OR-Tools 9.15.6755、PyInstaller 6.16.0。修改前的独立冷进程测量如下：

| 项目 | 修改前 |
|---|---:|
| 导入 `ortools.sat.python.cp_model` | 5,217.7 ms |
| 导入应用模块 | 6,451.4 ms |
| 已有系统文件缓存时导入应用模块 | 约 1,778.8 ms |
| 主窗口构造与首轮事件 | 约 260.9 ms |
| 0.9.0 单文件首次运行到应用模块加载完成 | 10.46 s |
| 0.9.0 单文件第二次运行到应用模块加载完成 | 4.20 s |

主要时间消耗不是棋盘构造，而是 `solver.py` 在应用模块导入时同步加载 CP-SAT，连带初始化 NumPy/Pandas 和原生运行库。恢复确认框又在 `MainWindow` 构造期间执行，此时父窗口尚未显示，Windows 没有稳定的可见窗口层级可供激活。

## 采用方案

1. 使用锁保护的延迟加载器保存 CP-SAT 模块；普通局部推理不会触发它，全局推理接口保持原样。
2. 主窗口首次绘制 250 ms 后启动 `SolverWarmupThread`，后台完成 CP-SAT 导入；应用退出时等待线程安全结束。
3. 把自动恢复检查移到主窗口第一次 `showEvent()` 后的下一轮事件循环。
4. 确认框作为可见主窗口的模态子窗口显示，随后调用提升和窗口激活；明确不设置永久置顶标志。
5. PyInstaller 阶段临时隔离 `PATH`，只允许项目 Python 环境和 Windows 系统目录参与 DLL 解析，完成后恢复调用者原环境。

## 修改后测量

每个导入数据来自一个全新 Python 进程；单文件数据从启动 EXE 到 Windows 报告主窗口句柄可见，连续运行三次。

| 项目 | 原始数据 | 中位数 |
|---|---|---:|
| 导入应用模块 | 437.2 / 459.1 / 434.3 / 443.0 / 431.8 ms | 437.2 ms |
| 只导入求解模块 | 51.7 / 52.2 / 49.4 / 51.3 / 51.8 ms | 51.7 ms |
| 后台预热 CP-SAT | 634.4 / 636.8 / 631.5 ms | 634.4 ms |
| 0.9.1 单文件到窗口可见 | 5,321.5 / 4,842.1 / 4,636.3 ms | 4,842.1 ms |

修改前的单文件数据记录的是“应用模块加载完成”，修改后记录的是更接近用户感知的“窗口句柄可见”，端点并不完全相同，因此只用于确认方向，不宣称精确倍数。可以确定的是，应用模块冷导入从数秒降到约 0.44 秒，首屏不再同步等待 CP-SAT。

## 未采用方案

- **增加 CPU/线程资源：** 启动瓶颈是导入链，不是可并行的求解任务；增加 CP-SAT worker 不会改善首屏。
- **启动前预计算求解步骤：** 会占用 UI 关键路径，并与用户之后选择的种子和手动盘面无关。
- **永久置顶确认框：** 虽能强制覆盖其他窗口，但关闭流程和多窗口使用体验更差；可见父窗口、模态关系和一次性激活已经足够。
- **排除 Qt QML/Quick/PDF 等组件：** 试验成品无法加载 QtCore，冻结冒烟失败，已全部撤销。
- **排除 Pandas：** 当前 OR-Tools 的 CP-SAT Python 模块直接依赖 Pandas，不能在未改写第三方包的情况下安全删除。

## 构建环境污染记录

一次裁剪诊断中，PyInstaller 从桌面工具注入的 Poppler 路径收集了不属于项目的 `icuuc.dll` 和 `icudt78.dll`，导致冻结版 QtCore 无法加载。最终构建脚本在 PyInstaller 子步骤中使用隔离 DLL 搜索路径；正式 Analysis 不再包含该外部运行库。这个问题与业务代码无关，但若不加门禁，会让同一源码在不同开发终端得到不同成品。

## 正确性门禁

- 102 项源码测试全部通过，其中包含紧凑操作栏的文字、宽度和无障碍属性回归。
- 新增独立进程回归：应用导入和普通局部推理期间 CP-SAT 保持未加载，显式预热后可用。
- 恢复接受/放弃两条分支均验证：构造期不弹窗，主窗口显示后才询问，父窗口当时可见。
- 确认框验证提升、激活请求以及不存在 `WindowStaysOnTopHint`。
- 原生 Windows 平台实测中，确认框句柄与 `GetForegroundWindow()` 返回值一致，父窗口可见且确认框处于活动状态。
- 正式单文件构建通过完整 UI、存档、模拟推演、Easy/Hard seed 1 和缓存命中的冻结成品冒烟。
